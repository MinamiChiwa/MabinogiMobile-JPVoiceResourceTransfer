# 0.1.8 露娃之歌修正

## 问题

0.1.7 把 `BGM_Sub_Quest_LuaSong` 换成了日服版本，但游戏里露娃唱歌时仍是台服人声。

台服客户端里还有一份 `BGM_SNL_Sub_Quest_LuaSong`（`audioclips/snl/`），解码后与台服 `BGM_Sub_Quest_LuaSong` 逐采样相同，任务实际播放的是这份副本。日服客户端也带着同一份副本，内容同样是台服人声；只有日服的 `BGM_Sub_Quest_LuaSong` 是日语人声。因此按同名匹配时，这份副本即使被选中也只会得到相同的音频。

## 修正

- 新增来源别名：台服 `BGM_SNL_Sub_Quest_LuaSong` 使用日服 `BGM_Sub_Quest_LuaSong` 作为来源，报告中 `match_kind` 为 `alias`。
- 别名优先于同名匹配，不会误用日服里同为台服人声的 SNL 副本。
- 当前台服客户端的目标数 8328 → 8329。
- 语音索引格式升级为 3，旧的 `.voice-index-cache` 会自动重建。
- 内置缓存无需更新：别名来源 `BGM_Sub_Quest_LuaSong` 已在缓存中。

按大小和时长排查了全部未选中的台服音频，没有其他与日台不同语音重复的副本；尺寸碰巧相同的几项都是日台一致的音效。

## 已用 0.1.7 替换的客户端

只需要更新 `AssetPackages/0733.blob`。0.1.7 不会改动这个文件，所以也可以用 0.1.8 从纯净台服重新生成全部内容。

## 验证

122 项回归测试通过（4 项因可选编码器或符号链接权限跳过）。在纯净台服 `0527.blob` 和 `0733.blob` 的副本上实际写入：两首曲目都变为日服音频（SHA-256 `f2d4a574…`），两个 blob 中其余 178 个音频对象不变，原始台服文件未被修改。
