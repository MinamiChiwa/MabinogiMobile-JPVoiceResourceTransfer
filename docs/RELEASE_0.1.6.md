# 0.1.6 修复说明

## 部署

便携版携带Python、Tkinter、UnityPy及本地音频解码依赖。用户完整解压后直接运行，不需要安装Python或在线下载依赖。运行环境自检覆盖Tk、FSB5解码和多进程扫描。源码版保留独立虚拟环境安装路线，适合开发者。

## 进度

扫描台服0–10%，扫描/加载日服10–20%，复制20–50%，替换及逐包校验50–95%，报告收尾95–99%。这些比例是阶段预算，不代表预计剩余时间；每个阶段同时显示实际计数。只有进程正常退出、报告确认成功且用户未取消，才显示100%并弹出完成提示。完成后的迟到事件和上一轮事件不能重新启动动画。

## 语音调查

本次核对用户提供的0.1.5工具包、已替换客户端和纯净备份，没有修改原目录。旧报告列出8254次替换；实际音频全部等于缓存，名称/容器匹配没有漏掉Flora。

其中634个音频对象（539个不同名称/容器键）与纯净台服原音频也相同。NPC子集包含22个NPC名称下的365个对象（280个不同键）。这些是需要进一步核实来源内容的候选，不能直接据此断言全部都是韩语。

Flora共45条目标：41条缓存音频不同于台服，4条完全相同：

| 台词 | 缓存来源 | 结果 |
|---|---|---|
| `Vo_NPC_Flora_OpenShop_01` | `AssetPackages/0638.blob` | 与台服开店原音频相同 |
| `Vo_NPC_Flora_Thank_01` | `AssetPackages/0638.blob` | 与台服原音频相同 |
| `Vo_NPC_Flora_Wow_01` | `AssetPackages/0638.blob` | 与台服原音频相同 |
| `Vo_NPC_Flora_Wow_02` | `AssetPackages/0638.blob` | 与台服原音频相同 |

WAV归档中这四个文件完全相同，且这一重复音频被54个不同文件名复用。不能把它们当作四句独立的日语台词。程序继续采用压缩缓存/日服客户端来源，不会自动拿不相关的WAV覆盖。

旧缓存生成器按压缩数据大小挑选同名/同容器版本；并行版本遇到同大小且内容不同的来源时受完成顺序影响。现有缓存未保存所有被丢弃的候选，因此缺少原日服客户端时无法追溯是否曾有正确日语版本。此问题应在重新采集资源时保留来源与冲突记录，不能仅凭大小判断语言。

0.1.6区分音频来源相同、实际替换及失败，并提供逐项审计工具。程序层面的匹配、报告与完成提示已围绕此区别设计；Flora这四句仍需要可靠的对应日语资源才能补齐。

## 检验范围

回归测试、便携运行环境检查以及真实Flora资源重建均在独立工作目录执行。未启动游戏，也未验证游戏内播放。正式发布前建议使用独立Windows新环境和游戏内人工验收。
