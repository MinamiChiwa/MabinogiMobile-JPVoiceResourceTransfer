# 0.1.6 接手修复设计

用户要求修复新环境依赖部署、依赖安装速度、Flora 商店语音漏替换及阶段进度/完成提示。

## 部署与源码

以仓库 0.1.5_nojp 发布入口和资源处理代码为基础，将 tools/ 作为唯一维护源码，发布文件由构建脚本生成。保留自带缓存与用户日服目录两种来源。提供 Windows x64 PyInstaller onedir 便携包，包含 Python、Tk、UnityPy 及其音频解码依赖。用户运行便携包不安装 Python、不运行 pip、不访问网络；源码开发安装使用独立环境。

## 语音覆盖

逐项对比纯净台服、现有输出及本地日服缓存的压缩音频哈希，核实 Flora OpenShop 与全部对象的同类情况。名称/容器精确匹配仍为首选；禁止凭猜测将不同台词或 NPC 互换。若来源本身与台服相同，报告为来源相同、未产生有效变化，而不声称已完成语言替换。缺失来源和重复名称歧义必须列出。

## 进度

资源进程发出结构化阶段事件。界面分别显示阶段与当前/总量，整体进度为阶段预算；扫描不再占据90%。复制与重建提供真实计数，完成前最高99%。进程成功且报告确认完成后，进度100%、动画停止、弹出完成提示；失败和取消没有成功弹窗。忽略已结束运行的迟到事件。

## 验证与边界

修复原有测试的失效路径，执行回归测试、静态编译、便携包在无 Python PATH 和中文空格目录下的运行验证，以及真实 Flora 独立输出重建。现有游戏目录和本地工具包只读；实际重建测试输出在 work/。GitHub 不分发客户端语音，不修改官方 manifest，不运行或改动任何注入/绕过代码。
